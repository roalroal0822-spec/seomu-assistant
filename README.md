# 서무비서 (서무 절차 안내)

2026 공공 AI 대전환 챌린지 세션2 지정과제 · **과제② 서무비서** 출품작

기관의 서무 규정·지침·서식을 넣어 두면, 담당자가 "어제 부산 출장 다녀왔어요"처럼 상황을 말할 때마다 해당 절차와 근거 조문, 단계별 기한(날짜 계산), 필요한 서류·서식, 결재선, 여비 계산까지 안내하고 서식 초안을 채워 주는 비서형 도구입니다.

## 접속 주소

실행하면 브라우저가 자동으로 열립니다. 열리지 않으면 **http://localhost:8102** 로 접속하세요.
(포트 변경: `python run.py --port 9000` 또는 `config.json`의 `port`)

## 실행 방법

필요한 것: Python 3.10 이상(3.10·3.11·3.13에서 구동 확인), 인터넷(처음 한 번 라이브러리 설치). 모델은 없어도 됩니다.

- **Windows**: `run.bat` 더블클릭 (처음 실행 때 실행 환경을 만들고 라이브러리를 설치한 뒤 시작)
- **macOS·Linux**: `./run.sh`
- **직접 실행**:
  ```
  pip install -r requirements.txt
  python run.py
  ```
- **실행 파일(.exe) 만들기(선택)**: Windows PC에서 `tools\build_exe.bat` 실행 → `dist\seomu-assistant\seomu-assistant.exe` (이 실행 파일 만들기는 Windows 환경에서 아직 시험하지 못했습니다)
- 종료: 실행 창에서 `Ctrl+C`

## 주요 기능

### 기본기능
- **규정에서 업무별 절차 카드 자동 생성**: 규정의 조문을 읽어 단계·기한·필요 서류·서식·담당 부서를 뽑습니다(근거 조문 표시).
- **상황 말하기 → 절차 안내**: 상황 문장에서 날짜·기간·출장지·금액 등을 읽고 지금 해야 할 단계와 남은 기한, 지난 단계를 알려 줍니다.

### 선택기능(구동되는 수준으로 구현)
- **서식 초안 작성**: 해당 단계 서식(hwpx)을 골라 내 정보·상황·여비 계산 결과로 채운 새 파일을 만듭니다(원본 서식은 그대로).
- **다음 할 일·기한 안내**: 접수한 일을 '처리 이력'에 남기고 단계별 완료 표시, 기한 지남 표시
- **결재선 정리**: 위임전결 기준표에서 결재선을 찾아 안내
- **규정 개정 시 절차 갱신**: 개정 규정 파일을 올리면 신구조문대비와 바뀌는 절차(기한·서류)를 먼저 보여 주고 확인 후 반영, 이전 판 보관
- **층 관리**: 공통 기준·기관 규정(관리자 등록)·개인 보충 메모(사용자 등록)를 층으로 나눠 관리, 기관 규정이 공통 기준과 다르면 표시
- **처리 이력**: 접수·단계 처리·서식 작성·규정 변경 기록

## 작동 방법 (시연 순서)

1. 실행하면 브라우저가 열립니다(`http://localhost:8102`). 처음 실행 때 모의 규정집이 작업 폴더에 자동으로 복사됩니다.
2. **상황 말하기**에서 예시("출장 다녀와서 정산해야 해요. 어제 부산에서 1박 2일로 다녀왔어요")를 누르고 "안내 받기"를 누릅니다.
3. 단계별 기한·근거 조문·결재선·여비 계산을 확인하고, 단계 옆 서식 버튼으로 서식 초안을 내려받습니다(먼저 **내 정보** 입력 권장).
4. **다음 할 일·처리 이력**에서 단계를 완료 처리합니다.
5. 오른쪽 위 사용자 구분을 '관리자'로 바꾸고 **규정 개정 반영**에서 "시연용 개정본 사용"을 누르면 신구조문대비와 바뀌는 절차가 보입니다. "이대로 반영"을 누르면 절차 카드가 갱신됩니다.
6. **업무별 절차**, **규정·서식 관리**(3개 층 등록), **작업 기록**을 확인합니다.

발표·영상용으로 장면별 화면 조작과 설명을 정리한 대본은 [시연대본.md](시연대본.md)에 있습니다.

## 모델(LLM) 연결과 교체

- 모델 없이도 모든 기능이 규칙 기반으로 동작합니다. 모델을 연결하면 상황 문장을 읽어 알맞은 절차를 고르고 날짜·출장지 등 정보를 보태며, 안내 문장을 덧붙입니다(후보에 없는 절차는 쓰지 않음).
- 화면 오른쪽 위 **모델 배지**를 누르거나 `config.json`(예시: `config.example.json`)에서 바꿉니다. 코드 수정은 필요 없습니다.
- 지원 방식
  - `openai`: OpenAI 호환 API(`/v1/chat/completions`) — vLLM, Ollama(`/v1`), LM Studio, 행정안전부 AI 공통기반 등
  - `ollama`: Ollama 기본 API(`/api/chat`)
- 환경변수로도 바꿀 수 있습니다: `LLM_PROVIDER`, `LLM_BASE_URL`, `LLM_MODEL`. API 키는 파일에 적지 않고 환경변수(기본 `LLM_API_KEY`)로만 읽습니다.
- 예) Ollama: `ollama pull gemma3:4b` 후 연결 방식 `openai`, 주소 `http://localhost:11434/v1`, 모델 `gemma3:4b`
- 모델이 낸 결과는 그대로 쓰지 않고 원문과 대조해 검증합니다(근거 위치·현행 조문에 실제로 있는지). 검증에 걸린 제안은 버리고 그 사실을 화면에 표시합니다. 모델 호출이 실패하면 규칙 기반 결과로 계속 진행합니다.

### 2종 이상 모델 검증 방법

```
python tools/verify_models.py --base-url http://localhost:11434/v1 --models gemma3:4b exaone3.5:7.8b
```
모델별·기능별 통과 여부와 걸린 시간을 `verify_report.md`로 남깁니다. `--mock`을 붙이면 출력 습관이 다른 가짜 모델 2종으로 연결 경로만 시험합니다(실제 모델 성능 검증이 아님).

> 현재 상태: 개발 환경에서 실제 모델을 내려받을 수 없어, 가짜 모델 2종으로 OpenAI 호환·Ollama 두 방식의 연결 경로만 확인했습니다(전 항목 통과). 실제 모델 2종 검증은 위 명령으로 실행해 보고서를 함께 제출하는 것을 권장합니다.

## 자료 사용과 원본 보호

- 함께 넣은 `sample_data/`는 가상의 기관 **가람구시설관리공단** 기준으로 지어낸 모의자료입니다. 실제 기관·인물·연락처와 관계없습니다. (`tools/samples_seomu.py`로 다시 만들 수 있습니다)
- 투입한 원본 파일은 읽기만 합니다. 규정·서식을 올리면 작업 폴더(data/kb)에 사본으로 저장하고, 서식 초안은 원본 서식을 복사해 새 파일로 만듭니다. 규정을 개정 반영할 때 이전 판을 보관합니다.
- 작업 데이터와 산출물은 `data/` 폴더(설정 `data_dir` 또는 환경변수 `APP_DATA_DIR`로 변경)에만 저장합니다. 데이터베이스 설치가 필요 없습니다.

python tests/smoke_test.py        # 서버를 임시 폴더로 띄워 주요 기능을 차례로 호출(모델 없이)
python tools/verify_models.py --mock   # 모델 연결 경로 시험

## 폴더 구조

```
run.py              실행 진입점 (브라우저 자동 열림)
app.py              웹 API
knowledge.py        기능 로직
assistant.py        기능 로직
forms.py            기능 로직
static/             화면(HTML·JS, 외부 라이브러리 없음)
core/               공통 모듈: 문서 읽기(hwpx·hwp·docx·pdf·xlsx·eml·txt), 검색, 모델 연결, 문서 내보내기(hwpx·docx·md), 저장소, 웹 서버
sample_data/        모의자료
tools/              모델 검증 도구, 가짜 모델 서버, 모의자료 생성기
tests/              구동 점검
data/               작업 데이터·산출물 (실행 시 생성, 저장소에 올리지 않음)
```

## 정식 활용(정보화사업) 이관 메모

- 파이썬 표준 라이브러리 웹 서버 + 바닐라 JS로 만들어 외부 프레임워크 의존이 적습니다. 기능 로직(`knowledge.py, assistant.py, forms.py`)은 웹 계층과 분리되어 있어 다른 프레임워크로 옮기기 쉽습니다.
- 바꾸기 쉬운 연결 지점: 저장소(`core/store.py`, JSON 파일 → DB), 모델(`core/llm.py`, 설정만으로 교체), 문서 읽기(`core/loaders.py`), 문서 내보내기(`core/export.py`)
- 로그인·권한은 시연 범위에서 단순화했습니다(정식 구축 시 기관 인증 연동 필요).

## 알려진 한계

- 절차 추출은 '…일 전까지', '…날부터 …일 이내'처럼 공공기관 규정에서 흔한 문장 형식을 기준으로 합니다. 표현이 다르면 관리자가 **업무별 절차**에서 카드를 고칠 수 있고, 고친 카드는 규정이 바뀌어도 유지되며 '검토 필요'로 표시됩니다.
- 공휴일은 계산에 넣지 않습니다(달력 기준 일수).
- 한글 HWP(5.0) 파일 읽기는 실제 HWP 파일로 시험하지 못했습니다(HWPX는 시험함).
